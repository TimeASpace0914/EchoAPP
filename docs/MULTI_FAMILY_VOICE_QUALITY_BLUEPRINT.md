# 迴響多家屬聲音身份與品質保證藍圖

## 目標

迴響的核心價值不是「把任一音檔變成可播放的語音」，而是讓每一個家屬在適當授權與資料保護下，取得**像其親友、讀音可靠、情感自然且可重複使用**的聲音結果。系統不應將不同親友的樣本混用，也不應讓每次生成都以未驗收的新樣本重新建立克隆聲音。

> **基本原則：一位親友、一個受管控的聲音身份；同一身份只使用已驗收的 Profile 生成。**

## 現況品質缺口

目前流程在沒有 `voiceProfileId` 時，以 `echo_時間戳` 建立新 Profile，再立即生成。此做法雖可快速完成單次體驗，卻不適合多家屬正式使用：它沒有聲音身份資料庫、沒有樣本品質閘門、沒有家屬核可、也沒有可回退的 Profile 版本。

| 現況 | 風險 | 改善方向 |
|---|---|---|
| 每次上傳可能建立新 Profile | 同一人每次音色不同；品質低的樣本立即投入生成 | 先建立「候選聲音身份」，經預覽核可後才設為正式 Profile |
| 參考文字可留空或過短 | Qwen 無法正確對齊咬字、口音與節奏 | 將逐字參考文字列為必要品質資料；Whisper Large 僅作初稿，須由家屬確認 |
| 所有 Profile 平鋪於 Voicebox | 不同家庭可能誤選或誤用他人聲音 | 建立家庭工作區、聲音身份、Profile 版本與存取權限的關聯 |
| 沒有固定驗收文本 | 家屬只能在正式生成後才發現不像 | 先產生固定三段預覽，讓家屬確認音色、情緒與罕見字 |
| 沒有版本回退 | 新增樣本後品質退化，無法回到最佳版本 | 保留已核可版本為「正式」，新增樣本只產生候選版本 |

## 建議資料模型

### 家庭工作區與聲音身份

每一個家庭工作區代表一個家屬群組；每一個聲音身份代表一位特定親友。Voicebox Profile ID 必須被封裝在聲音身份下，而不是直接讓前端自由輸入或列舉。

| 實體 | 主要欄位 | 用途 |
|---|---|---|
| `FamilyWorkspace` | `id`、`displayName`、`accessPolicy` | 隔離不同家屬資料與使用紀錄 |
| `VoiceIdentity` | `id`、`familyId`、`memorialName`、`relationship`、`status`、`approvedProfileVersionId` | 一位親友的完整聲音身份 |
| `VoiceProfileVersion` | `id`、`voiceIdentityId`、`voiceboxProfileId`、`status`、`qualityScore`、`referenceText`、`stylePrompt` | 同一親友的候選／正式／封存聲音版本 |
| `VoiceSample` | `id`、`profileVersionId`、`duration`、`transcript`、`sourceQuality`、`reviewState` | 每段原始參考音檔與品質資料 |
| `PronunciationRule` | `id`、`voiceIdentityId`、`term`、`phoneticProxy`、`zhuyin`、`approved` | 特定親友常見的人名、宗教用語或方言讀音 |
| `GenerationRecord` | `id`、`familyId`、`voiceProfileVersionId`、`inputText`、`audioUri`、`resultStatus` | 每次生成必須可追溯到哪一個正式版本 |

`VoiceProfileVersion.status` 建議採用：`draft`、`processing`、`needs_review`、`approved`、`superseded`、`archived`。正式生成只能使用 `approved`，且每位親友同時間只允許一個 `approved` 版本。

## 家屬端標準流程

### 1. 建立親友聲音身份

家屬先建立親友名稱、關係與聲音描述。介面應明確顯示這是「親友的專屬聲音身份」，而不是一次性上傳欄位。系統應要求使用者確認其有權提供、保存及生成該聲音。

### 2. 上傳與品質前檢

候選音檔不應直接投入正式生成。系統先檢查是否為單一說話者、是否有過度背景音樂或多人交談、音檔時長是否足夠、音量是否穩定。建議最低可接受樣本為 20 秒；較可靠的目標為 45–90 秒的自然對話。

逐字參考文字是品質門檻的一部分。系統可使用 Whisper Large 產生草稿，但必須讓家屬檢視並修正人名、數字、台語詞、宗教用語與語助詞後才建立候選 Profile。

### 3. 三段固定預覽與家屬核可

候選 Profile 建立後，系統自動產生三段短語音，避免家屬只聽到單一幸運或失敗結果。

| 預覽 | 目的 | 建議內容 |
|---|---|---|
| 自然對話 | 檢查音色、呼吸、節奏 | 「今天的天氣很好，記得照顧自己。」 |
| 情感表達 | 檢查情緒是否自然 | 「我很想念你，也希望你一切都好。」 |
| 家屬專屬文本 | 檢查人名與罕見字 | 家屬提供的稱呼、姓名與固定用語 |

家屬針對「像不像本人、文字正不正確、情感自然度」各給 1–5 分。建議在三項都達到可接受門檻、且沒有關鍵錯字時，才能按下「確認為正式聲音」。未通過時，系統引導更換或增補樣本，不應讓低品質候選版本直接服務家屬。

### 4. 正式生成與新增樣本

家屬平日生成時，APP 固定使用該親友的 `approvedProfileVersionId`，不重新建立 Profile。若家屬上傳更好的錄音，系統建立新的候選版本與預覽，舊正式版本繼續可用；只有在新版本驗收通過後才切換。這可避免「今天比昨天更不像」卻無法回復的情況。

## 讀音與情緒的品質規則

讀音規則須掛在 `VoiceIdentity`，而不是全域混用。現有的同音代理規則可繼續保留：在 Qwen 合成前將已驗證的罕見字替換為同音常用字，但家屬看到、回憶庫保存的永遠是原始正字。家屬輸入 `字(注音)` 時，系統將其新增為待核對規則，而不是將注音直接朗讀。

情緒則採用「**一個主情緒＋一段短自訂提示**」。Profile 的長期口吻（例如自然台灣國語、語速偏慢）應儲存在聲音版本；單次生成只描述當下主情緒，避免「激昂、溫柔、開心」彼此抵銷。

## 資料隔離與隱私最低要求

多家屬正式使用前，不能只靠所有人共用一個 Voicebox Profile 清單。APP 後端應負責將每次請求限定於已授權的 `FamilyWorkspace` 與 `VoiceIdentity`；前端不應直接列出 Voicebox 的全部 Profile，也不應由使用者自行輸入 Profile ID。

目前透過 Cloudflare Tunnel 公開 Voicebox 的方式，應改為只有後端代理服務可存取的架構，並為家屬工作區加入登入或專屬安全存取碼。Profile 原始樣本、生成音檔、轉錄文字與讀音詞庫都需按家庭工作區隔離。任何刪除、匯出或新增樣本，都必須保留操作紀錄。

## 分階段落地建議

| 階段 | 優先功能 | 完成標準 |
|---|---|---|
| Phase 1：品質穩定 | 聲音身份庫、Profile 選擇、正式／候選狀態、固定三段預覽、人工參考文字確認 | 同一親友不再每次重建 Profile；家屬可回到已核可的最佳聲音 |
| Phase 2：家屬可用 | 家庭工作區、存取碼／登入、Profile 與生成紀錄隔離、樣本版本回退 | 家屬只看得到自己的親友與生成紀錄 |
| Phase 3：品質保證 | 音檔品質分析、家屬評分、專用詞庫審核、品質儀表板 | 不合格候選聲音不會進入正式生成 |
| Phase 4：營運優化 | 家屬通知、服務人員覆核、定期備份與可攜移轉 | 可追蹤每個聲音身份的品質與服務狀態 |

## 立即執行建議

在正式開放多家屬前，優先完成 Phase 1。最小可用版本應讓服務人員或家屬先建立「親友聲音身份」，上傳樣本、校正逐字文字、產生三段預覽並核可一個正式 Profile。生成頁只能選擇已核可聲音身份；新音檔只可建立候選版本，不會覆蓋既有最佳聲音。

這個流程會把品質控制前移到家屬第一次正式使用之前，讓迴響從一次性、不可預期的生成工具，變成可持續維護且能承接家屬信任的聲音紀念服務。
