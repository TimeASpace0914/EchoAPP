# 授權語音測試、系統預處理與家屬錄音黃金守則

## 適用範圍與承諾

本指南適用於**已取得明確使用授權**的自製錄音或開放授權語音素材。測試目的不是宣稱可對所有聲音達到完全相同的複製，而是以可重複的流程，提升音色相似度、文字正確性、情緒自然度與生成穩定性。

Qwen3-TTS Base 的克隆流程以參考音檔與對應逐字文字作為條件；官方也提供建立並重用 `voice_clone_prompt` 的方式，以避免每次重新萃取同一份參考特徵。[1] 對於家屬服務，這意味著正式生成必須固定使用已驗收的 Profile，而非每次以新音檔臨時建立聲音身份。

## 一、公開授權素材的測試方式與可觀察表現

### 可使用素材

僅使用明確為 CC0、Public Domain，或標示允許所需用途的音檔；使用前仍應保存授權頁面網址、授權類型、下載日期與素材 ID。最安全的首輪測試是由團隊成員自行錄製並簽署測試授權的樣本。

### 不以「聽起來像」作唯一判斷

可重複的品質測試應分為四個面向：文字正確性、音色相似度、韻律／情緒，以及系統穩定度。ClonEval 的公開方法以參考音檔與生成音檔的 speaker embedding cosine similarity 量化音色相似度，並另外評估情緒與聲學特徵；其論文也指出 WER 只能衡量文字正確性，不能代表克隆品質。[2]

| 測試面向 | 量測方式 | 通過判斷 |
|---|---|---|
| 文字正確性 | 以 ASR 回讀生成音檔，人工確認姓名、數字、宗教詞與專用詞 | 關鍵詞零錯誤；一般文字無影響理解的錯誤 |
| 音色相似度 | 固定原始樣本與生成樣本，使用 speaker embedding 相似度做內部比較 | 同一 Profile 的分數不應低於其已核可基準 |
| 韻律與情緒 | 家屬以 1–5 分評估自然度、親近感、情緒符合度 | 三段預覽平均至少 4 分才可正式啟用 |
| 穩定度 | 同 Profile、同設定連續生成 3 次 | 三次都完成，且關鍵詞、音色與速度無明顯飄移 |

### 建議的 3 × 3 授權測試矩陣

每一個授權聲音樣本使用三種文字：自然對話、帶情緒的關懷句、含人名／罕見字的專用句；再以三種輸入品質比較：乾淨原音、輕微環境音、明顯不合格樣本。只有「乾淨原音＋逐字文字＋固定 Profile」可作為服務品質基準；其他組別只用於驗證系統攔截是否正確。

## 二、系統端預處理與品質閘門

### 核心原則：先評估，再處理，再核可

系統不應對所有音檔套用激烈降噪或音色修復。過度處理可能刪掉辨識說話者的重要音色特徵；因此建議保留原始檔、產生可追蹤的處理副本，並在品質分數未達門檻時拒絕建立正式 Profile。

| 階段 | 系統處理 | 目的 | 建議規則 |
|---|---|---|---|
| 格式正規化 | 讀取檔案、轉為分析用單聲道 WAV 副本 | 讓品質分析與模型輸入一致 | 原始檔永久保留；轉檔檔僅供分析／模型使用 |
| 語音活動偵測 | 移除長靜音，估算實際人聲秒數 | 避免用空白或極短片段建立 Profile | 可理解人聲少於 20 秒時，不建立正式 Profile |
| 單一說話者檢查 | 偵測多人的說話區段 | 避免把家屬、主持人、背景人物混入同一聲音身份 | 多人比例顯著時要求家屬裁切單人片段 |
| 音量／失真檢查 | 偵測 clipping、過低音量、長期爆音 | 降低破音、金屬聲、音色漂移 | 發現 clipping 或過低訊噪時，標示「需要更換片段」 |
| 噪音與混響評估 | 評估背景音樂、電視聲、回音與環境聲 | 避免模型把環境特徵誤當成聲音身份 | 音樂或環境音壓過人聲時直接拒絕 |
| 參考文字核對 | Whisper Large 先轉錄，使用者校正專名與方言字 | 讓語音—文字配對可靠 | 未核對時僅能建立候選，不得正式啟用 |
| Profile 版本化 | 建立候選 Profile 與不可覆蓋的核可 Profile | 保留最佳音色並可回退 | 新樣本只能建立新版本，不能覆蓋既有最佳版本 |

### 可安全自動化的處理

可自動處理的項目是容器／取樣率正規化、前後長靜音裁切、音量過低警示、語音活動偵測、逐字轉錄初稿與品質報告。對於降噪、去混響、分離人聲，建議作為「候選處理版本」而非直接覆蓋；家屬或服務人員應能比較原始版本與處理版本的預覽。

Inworld 的語音克隆建議強調安靜環境、清晰且一致的發音、避免背景音樂與雜音、避免爆音，並指出較長且乾淨的提示音檔通常有助於提高瞬時克隆的相似度。[3]

## 三、家屬錄音黃金守則

> 這不是考試，也不需要完美演出。只要讓親友以平常的聲音、在安靜環境中連續說話，系統就能更好地保留熟悉的音色與說話節奏。

### 錄音前

| 要做 | 原因 |
|---|---|
| 選擇沒有電視、音樂、抽風機、多人談話的安靜空間 | 背景聲會被誤學為聲音身份的一部分 |
| 手機距離嘴巴約一個手掌，固定位置 | 太近容易爆音，太遠容易收進房間回音 |
| 關閉擴音、藍牙外放與手機殼摩擦來源 | 避免機械噪音與重複回授 |
| 使用手機原生錄音或 WAV／高品質 M4A | 優先保留原始聲音細節 |
| 準備 45–90 秒自然說話內容 | 可提供較完整的音色、停頓、速度與韻律資訊 |

### 錄音時

| 建議 | 不建議 |
|---|---|
| 像平常和家人聊天一樣，句子有陳述、提問、關心與簡短笑意 | 刻意朗讀、唱歌、耳語、長時間哭泣或情緒劇烈失控 |
| 口齒自然清楚、維持平常音量 | 壓低聲音、突然大喊、刻意模仿播音腔 |
| 說出常用稱呼、口頭禪與自然停頓 | 一段只有「嗯」、「測試測試」或無意義單字 |
| 若有特殊姓名、宗教詞、台語詞，事後逐字填入正確文字 | 完全依賴自動轉錄、不核對人名與罕見字 |

### 一分鐘示範稿

家屬可依親友平常語氣念出下列內容，也可改成其真正常說的話：

> 「今天的天氣很舒服，大家都要記得照顧自己。吃飯的時間到了，不要太忙忘了休息。看到你們平安、好好過日子，我就很安心。謝謝你一直陪在身邊，有空我們再好好聊一聊。」

內容應加入該親友常用的稱呼或口頭禪，但不必強迫包含敏感或悲傷語句。若使用既有生前錄音，應選擇單人、自然對話、背景乾淨且至少 20 秒可理解的片段。

### 上傳前 30 秒自我檢查

1. 這段音檔是否只有一個主要說話者？
2. 是否能清楚聽到每個字，且沒有背景音樂或電視聲？
3. 是否至少有 45 秒自然說話，或至少 20 秒可理解語音？
4. 我是否能提供與錄音完全一致的文字，並校正姓名與特殊詞？
5. 我是否有權使用這段聲音，且家屬已了解其用途？

只要任何一題為否，系統應優先請家屬換一段錄音，而不是直接產出低相似的正式語音。

## 四、給服務人員的首次體驗 SOP

| 步驟 | 服務人員動作 | 成功條件 |
|---|---|---|
| 1. 接收 | 說明授權與用途，收取原始檔 | 可追溯來源與使用授權 |
| 2. 預檢 | 確認單人、時長、噪音、音量與可理解度 | 通過品質門檻 |
| 3. 文字 | Whisper Large 初稿後逐字確認 | 姓名、稱呼、數字、台語／宗教詞已校正 |
| 4. 候選 | 建立候選 Profile，不覆蓋既有版本 | 候選可被追蹤與回退 |
| 5. 預覽 | 生成三段固定測試句 | 文字、音色、情緒都可接受 |
| 6. 核可 | 家屬確認或要求更換樣本 | 形成正式 Profile |
| 7. 正式使用 | 所有文案重用正式 Profile | 不會因新上傳檔破壞既有品質 |

## 五、對外溝通建議

應承諾「以合格樣本與核可流程，盡可能保留親友熟悉的聲音特徵」，而非承諾完全等同真人。當樣本本身不足或雜音過高時，主動要求更換片段，是對家屬體驗與逝者聲音尊重的一部分。
