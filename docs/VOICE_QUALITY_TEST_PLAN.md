# 迴響 APP：文字準確、生成速度、克隆真實感與情緒自然度測試指南

> **目標：** 用可重複的測試方式，找出每一位聲音個案在「文字正確、聲音相似、情緒自然、生成時間」之間最合適的平衡；先穩定量測，再調整 APP 與 Voicebox。

本指南以目前迴響的流程為準：APP 上傳參考音檔與可選參考文字，後端建立 Voicebox Profile，使用 `qwen` 引擎生成中文語音，並將情緒、語氣、語速與拼音提示傳入 `instruct`。目前每次首頁生成都會建立新的 Profile；因此第一次提升速度的重點，不是把文字調成更快，而是減少每次重複上傳／建立 Profile 的時間。

---

## 1. 四項目標的優先順序

請不要同時調整所有設定。建議依序先固定「參考音檔與參考文字」，再調整文字內容，最後才校正情緒與速度。這可以避免無法判斷究竟是音檔、轉錄、引擎或指令造成差異。

| 優先順序 | 目標 | 最重要的控制項 | 通過條件 |
|---:|---|---|---|
| 1 | 文字準確率 | 精確 `referenceText`、文字斷句、名字／數字標注 | 人工聆聽無漏字、錯字、同音誤讀 |
| 2 | 聲音相似度 | 乾淨且具代表性的參考音檔 | 聽得出原說話者的音色、咬字與節奏 |
| 3 | 對話自然度與情緒 | 單一主情緒、語境明確、自然停頓 | 不像播報或朗讀，情緒與內容一致 |
| 4 | 生成速度 | Profile 重用、模型常駐、文字分段、硬體資源 | 同等品質下總秒數可預期、穩定 |

---

## 2. 先建立「標準參考音檔」

克隆品質最主要由參考音檔決定。Qwen3-TTS 的 voice clone 模式使用「參考音檔 + 對應逐字文字」來建立更完整的上下文提示；官方也指出只使用 speaker embedding 而省略參考文字會降低克隆品質。[1] 因此，**參考文字的正確性比加入很長的情緒提示更優先**。

### 2.1 建議規格

| 項目 | 建議 | 避免 |
|---|---|---|
| 長度 | 20～45 秒，單一說話者 | 少於 8 秒、過長的拼接錄音 |
| 內容 | 日常自然對話，包含陳述、問句與自然停頓 | 唱歌、背稿、哭喊、口號、過度激昂片段 |
| 音質 | 近距離、穩定音量、低背景噪音 | 電視聲、多人交談、回音、風聲、嚴重壓縮 |
| 語言／口音 | 與預計生成語言及口音一致 | 以外語或不同口音樣本生成台灣中文 |
| 情緒 | 先用平靜自然版本作主樣本；另保留溫暖版本做 A/B 測試 | 只用極度悲傷或極度興奮片段做所有用途 |

> 建議先準備兩個合法取得、已獲授權的樣本：**A「日常中性」**與 **B「溫暖關懷」**。先用 A 找出最高文字準確率與聲音相似度，再比較 B 是否能改善溫柔對話的真實感。

### 2.2 參考文字要逐字正確

在 APP 的「參考文字」欄位，請盡量輸入錄音中**實際講出的每一個字**，包含語助詞、停頓語與口頭禪。例如音檔說「欸，你今天有沒有吃飯啊？」就不要只輸入「你有沒有吃飯」。

| 錄音實際內容 | 不建議輸入 | 建議輸入 |
|---|---|---|
| 「欸，你今天有沒有吃飯啊？」 | 你有沒有吃飯 | 欸，你今天有沒有吃飯啊？ |
| 「嗯……我想一下，晚點再跟你說。」 | 晚點再跟你說 | 嗯……我想一下，晚點再跟你說。 |
| 「蔡承諺，下班記得回家。」 | 下班記得回家 | 蔡承諺，下班記得回家。 |

語音轉錄（Whisper）可作為初稿，但對於人名、台語詞、地名、數字和語助詞，應由熟悉該說話者的人手動校正。APP 已會在生成文字中加入較長中文片段的拼音提示；這是針對罕見字 G2P 誤讀的輔助，不能取代正確的參考文字。

## 3. 第一輪：建立可比較的基準測試

選定一段參考音檔後，先固定所有條件：使用相同音檔、相同逐字參考文字、語速 `1.0`、不選情緒、不填個性設定、`qwen` 引擎。每個測試只改變一個因素。

### 3.1 建議測試語料

以下文字避免個資，可直接用於首輪測試。每一則請獨立生成並記錄耗時。

| 編號 | 測試目標 | 測試文字 | 觀察重點 |
|---|---|---|---|
| T1 | 基本清晰度 | 「今天的天氣很好，出門的時候記得帶一瓶水。」 | 漏字、咬字、節奏是否自然 |
| T2 | 對話感 | 「欸，你今天過得怎麼樣？有空再跟我說說。」 | 語助詞、問句尾音、是否像真人聊天 |
| T3 | 人名與罕見字 | 「蔡承諺，晚一點回家路上要小心。」 | 「承諺」讀音是否正確 |
| T4 | 數字與日期 | 「明天早上九點二十分，我們在第二會議室見。」 | 時間與數字是否讀對 |
| T5 | 溫暖關懷 | 「天冷了，記得多穿一件外套，別讓自己著涼。」 | 情緒是否溫暖而不做作 |

### 3.2 記錄表

每次生成完成後，將結果寫入下表。每一項採 1～5 分：1 分代表不可用，3 分代表可接受，5 分代表可直接交付。

| 日期／版本 | 樣本 | 測試 | 耗時（秒） | 文字正確 | 音色相似 | 自然度 | 情緒貼合 | 備註 |
|---|---|---|---:|---:|---:|---:|---:|---|
|  | A 日常中性 | T1 |  |  |  |  |  |  |
|  | A 日常中性 | T2 |  |  |  |  |  |  |
|  | A 日常中性 | T3 |  |  |  |  |  |  |

首輪的目的不是馬上得到最有情緒的聲音，而是找出「**文字正確且音色穩定**」的基準。建議門檻是：文字正確、音色相似與自然度都至少達 **4 分**；未達門檻時，先更換或清理參考音檔，而非增加更多情緒提示。

## 4. 提高文字準確率的實作方法

### 4.1 輸入文字請依語意斷句

文字不是越長越好。將長文切成 1～2 句、每段約 12～35 個中文字，通常更容易控制內容與停頓，也能在單一段生成失敗時降低重試成本。

| 不建議 | 建議 |
|---|---|
| 「今天我想跟你說謝謝你一直照顧我們我知道你很辛苦但是你還是總是關心大家所以今天你要記得好好休息」 | 「今天想跟你說，謝謝你一直照顧我們。\n\n我知道你很辛苦，但你總是關心大家。今天要記得好好休息。」 |

請保留必要的標點符號：逗號代表短停頓，句號代表完整收尾，問號有助於問句語調。不要用大量驚嘆號、連續省略號或表情符號強迫情緒，這容易造成不自然的誇張語調與讀法。

### 4.2 人名、專有名詞與數字

1. **人名與罕見字：** 首次測試時用 APP 自動拼音提示即可；若仍讀錯，改寫為可讀形式後測試，例如以同音常用字暫代僅供比對，找出 G2P 問題範圍。
2. **數字：** 重要的金額、日期與時間，優先寫成中文口語形式。例如「9:20」改成「九點二十分」，「2026 年」改成「二零二六年」。
3. **英文縮寫：** 第一次先寫完整中文讀法，例如「AI」改成「人工智慧」，確定表現後再測縮寫。
4. **台語或特定家族說法：** 務必先以實際錄音中出現的字詞寫入 `referenceText`；若生成文本包含罕見用詞，先單獨做短句測試。

### 4.3 正確使用「參考文字」與「個性設定」

| 欄位 | 應填內容 | 不應填內容 |
|---|---|---|
| 參考文字 | 參考音檔逐字內容 | 「請溫柔一點」、「語速快一點」等控制指令 |
| 聲音描述 | 「中年男性、聲音偏低、說話沉穩」等聲音事實 | 與音檔不一致的想像描述 |
| 個性設定 | 對此次生成的單一說話方式描述 | 多個互相衝突的情緒與冗長故事 |

## 5. 讓克隆聲音更像真人

Qwen3-TTS 的 Base 模型可用參考音檔與對應文字進行 voice clone，並允許將已建立的 voice clone prompt 重複使用，避免重新計算提示特徵。[1] 對目前 APP 而言，代表最具效益的優化方向是「提高參考樣本品質」與「讓同一參考音檔的 Profile 可重複使用」。

### 5.1 參考音檔採樣策略

建議各聲音個案建立「樣本包」而不是只保存一個檔案：

| 樣本 | 用途 | 特徵 |
|---|---|---|
| `neutral_01` | 文字準確、日常對話基準 | 平靜、清楚、自然語速 |
| `warm_01` | 關懷與家庭對話 | 溫柔但不哽咽，句尾自然 |
| `bright_01` | 開心、鼓勵情境 | 音量穩定、笑意輕微、不尖叫 |

每次生成只選一個與目標情境接近的樣本。不要把不同年份、年齡差異大、麥克風差異明顯或多人片段串成同一檔案；這會使模型學到不一致的音色與空間感。

### 5.2 語句寫得像「說話」，不要像「文稿」

更像真人的關鍵常常是文本內容本身。優先使用短句、稱呼、自然口頭語與明確對話對象；避免書面長句與連續抽象形容詞。

| 偏朗讀腔 | 較自然的對話腔 |
|---|---|
| 「願你在人生道路上秉持堅毅精神，勇敢邁向未來。」 | 「你慢慢來就好，真的遇到困難，再跟我說。」 |
| 「請務必注意身體健康並妥善安排作息。」 | 「最近有沒有早點睡？不要又忙到太晚喔。」 |

## 6. 讓情緒起伏貼近真實對話

Qwen3-TTS 支援以自然語言指令調整情緒、語速與韻律，但指令必須與文字語意、參考聲音特質相容。[1] 目前 APP 會把「個性設定」加上選定情緒與「台灣國語口吻」組成 `instruct`；因此最有效的使用方式是：**一次只指定一個主情緒，再加一個可聽見的表達行為。**

### 6.1 操作原則

1. **首輪只選一個情緒標籤。** 多選「溫柔、開心、思念、激昂」等可能互相抵消，造成模型只輸出平淡中間值。
2. **情緒必須符合文字。** 若文本是關懷內容，優先用溫柔／關心；若文本是鼓勵內容，優先用鼓勵。不要讓「平靜文字」要求「極度激昂」。
3. **情緒強度從低到高測試。** 先測自然表達，再逐步加入「明顯但不誇張」，不要一開始就用「非常、極度、到極致」。
4. **在文字中加入自然停頓，而非用長指令硬控。** 合理標點通常比冗長指令更穩定。

### 6.2 可直接貼入「語氣與個性設定」的短提示

以下提示應一次只用一個，並搭配對應情緒標籤。請控制在 APP 的字數限制內。

| 場景 | 情緒標籤 | 個性設定範例 |
|---|---|---|
| 日常溫柔關心 | 溫柔 | `像熟悉家人自然聊天，音量柔和。關鍵字前短暫停頓，句尾自然收尾，不要播報腔。` |
| 輕鬆開心 | 開心 | `像剛聽到好消息，自然開心、語調明亮，帶一點笑意但不要誇張。` |
| 安靜思念 | 思念 | `像想念家人時輕聲說話，節奏稍慢，有自然停頓；不要哭腔或刻意顫抖。` |
| 溫暖鼓勵 | 鼓勵 | `語氣堅定溫暖，重點字稍微加重，像在真心替家人加油。` |
| 平靜交代 | 平靜 | `平穩清楚、像坐在身邊慢慢說話，保持自然呼吸與停頓。` |

### 6.3 情緒 A/B 測試法

固定 T5「天冷了，記得多穿一件外套，別讓自己著涼。」與相同參考音檔，依下列順序測試：

| 版本 | 情緒 | 個性設定 | 判讀 |
|---|---|---|---|
| E0 | 不選 | 空白 | 自然度基準 |
| E1 | 溫柔 | 空白 | 觀察標籤本身影響 |
| E2 | 溫柔 | 使用「日常溫柔關心」短提示 | 觀察是否增加真實停頓與收尾 |
| E3 | 關心 | 使用同一短提示 | 比較關切感是否太重 |

保留分數最高的版本作為該聲音 Profile 的預設組合。這會比所有個案使用同一組強烈情緒提示更可靠。

## 7. 提升生成速度，但不犧牲品質

### 7.1 先釐清「語速」與「生成速度」不同

APP 的 `speed` 參數用於控制輸出的說話快慢，**不等於模型計算速度**。把語速從 `1.0` 調成 `1.3` 可能改變音檔時長，但通常無法顯著縮短 Voicebox 的模型載入、Profile 分析與推論時間。

| 想改善的現象 | 優先做法 | 不建議做法 |
|---|---|---|
| 等待生成時間太久 | 重複使用已建立的 Profile、保持模型常駐、縮短單次文本、確認硬體資源 | 只把輸出語速調快 |
| 聲音講太慢 | 將語速從 1.0 微調到 1.05～1.15 | 直接調到 1.5 以上，易失去自然停頓 |
| 文字較長造成失敗或不穩 | 分段生成、各段保留完整標點 | 一次塞入大量長文 |

### 7.2 目前最優先的工程優化：Profile 重用

現在首頁每次生成若未提供 `voiceProfileId`，會重新上傳參考音檔並建立 Profile。這會增加網路傳輸、音檔處理與 Voicebox 分析的等待時間。下一個建議開發項目是：

1. 使用者上傳音檔後，第一次建立 Voicebox Profile。
2. 將 `profileId` 與音檔指紋、名稱、建立時間儲存至本機或後端。
3. 同一音檔後續改文字、改情緒、改語速時，直接重用 `profileId`。
4. 使用者明確按「更換音檔」或 Profile 失效時才重建。

這能減少重複上傳與分析，是**不犧牲音色品質**的首要速度優化。Qwen3-TTS 官方也提供重複使用既有 clone prompt 來避免重算 prompt features 的機制。[1]

### 7.3 推論服務調校順序

| 優先級 | 調校措施 | 預期影響 | 風險／注意事項 |
|---:|---|---|---|
| P0 | Voicebox 模型常駐，不在每次請求重新載入 | 大幅降低首段等待 | 需要足夠 RAM／VRAM |
| P1 | 重用 Voicebox Profile | 降低每次生成前置時間 | 需實作 Profile 管理與失效處理 |
| P2 | 文字以語意段落拆分 | 降低單次失敗與等待 | 合併播放時需處理段落接縫 |
| P3 | 使用 GPU、確認 GPU 推論未回退 CPU | 可顯著改善長文字推論 | 需檢查 CUDA／模型相容性 |
| P4 | 比較不同引擎 | 可能提升速度或文字準確 | 必須用同一測試語料比較，不可憑單次感覺切換 |

Qwen3-TTS 官方模型說明指出 0.6B 和 1.7B 均具串流能力，而模型大小、部署方式與硬體會影響實際延遲；因此您應測量自己的 Voicebox 環境，而非直接採用官方理想延遲數字。[1] [2]

## 8. 建議的實測順序（第一次測試可直接照做）

1. 選擇 **20～45 秒單人、低雜音、自然說話**的測試音檔。
2. 手動填入逐字正確的「參考文字」。
3. 生成 T1～T4：語速 `1.0`、不選情緒、個性設定留白。
4. 若 T1～T4 任一文字正確度低於 4 分，先修正參考文字或更換參考音檔，**不要先加情緒**。
5. 基準通過後，使用 T5 做 E0～E3 情緒 A/B 測試。
6. 對最佳結果微調語速：`0.95`、`1.0`、`1.05`、`1.10`，一次只改一格。
7. 記錄每次總耗時；若同音檔的第二次生成仍明顯耗時，列入 Profile 重用功能的優先開發項目。
8. 將每個個案的「最佳音檔、精確參考文字、最佳情緒與個性設定」保存為聲音檔案卡，後續生成沿用。

## 9. 何時需要進一步修改 APP

當完成至少 5 個基準測試、2 組情緒 A/B 比較後，再決定是否實作工程調整。建議優先級如下：

| 優先級 | 改進功能 | 解決問題 |
|---:|---|---|
| 1 | Voicebox Profile 重用與聲音檔案卡 | 同一音檔反覆生成太慢 |
| 2 | 「精確參考文字」必填提醒與轉錄校對頁 | 文字錯誤、罕見人名誤讀 |
| 3 | 每個 Profile 儲存預設情緒與個性設定 | 每次都要重填且風格不一致 |
| 4 | 多段文字佇列與合併播放 | 長文生成慢、易失敗、語氣不穩 |
| 5 | 品質測試紀錄頁 | 無法客觀比較引擎、樣本和提示效果 |

---

## 10. 隱私與使用原則

語音樣本、參考文字、生成內容可能包含個人資訊。測試階段請使用已獲合法授權的音檔與內容；測試紀錄不要保存完整個案音檔或識別性文字到公開試算表、GitHub 或未受控的雲端位置。
